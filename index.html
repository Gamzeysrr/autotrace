REQUIRED TO PUBLISH

An institution session alone cannot publish a report. The record appears in search only after the AutoTrace Rust program transaction is approved in Phantom and verified by the server. Only the record ID and SHA-256 digest are written on-chain; the VIN and report text stay off-chain.

A Solana transaction is required. Phantom signs the AutoTrace program transaction; the AutoTrace session provides institution authorization. Devnet is a test network.

HOW IT WORKS

How AutoTrace works

A verification layer that connects vehicle-history records to their sources.

Institution submits a recordInsurance · inspection · service
Source is attributableAuthorized institution key
Hash is anchoredSolana timestamp
History becomes visibleVIN + access permission

Product vision

An insurer submits an accident record.

The accident report and damage fields are linked to a VIN and digitally signed by an authorized institution.

An inspection firm submits a vehicle inspection report.

Part-level condition and report version are recorded with their source and timestamp.

A buyer searches the vehicle history with permission.

The buyer can see which institution submitted a report and whether its integrity has been verified.

What blockchain can and cannot do

✓
CAN: reveal later changes.If the current document hash differs from the anchored hash, the content has changed.
!
CANNOT: make false original information true.Source verification, institutional signatures, and trusted data integrations are still required.

This hackathon prototype demonstrates server-side access control with fictional institution accounts. It has no real institution integration, legal-entity verification, or production-grade infrastructure.
